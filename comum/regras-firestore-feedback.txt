// Kit Fácil 2 · regra do Firestore para receber as avaliações e os relatos de problema dos apps do projeto.
//
// Onde colar: console do Firebase → projeto conta-facil-2c1f9 → Firestore Database → Regras.
// Troque o bloco `match /feedback/{id} { ... }` que já existe por este (o bloco de /mesas, da comanda ao vivo,
// continua igual). Depois toque em Publicar.
//
// O que mudou em relação à versão anterior: o relato de problema pode mandar `categoria` e `gravidade`.
// Enquanto esta versão não for publicada, os apps mandam essas duas informações dentro do texto da mensagem,
// então nenhum relato se perde.
//
// O que a regra faz: qualquer aparelho pode CRIAR uma avaliação, mas só no formato do Kit Fácil (campos,
// tipos e tamanhos conferidos). Ninguém lê, altera nem apaga pelos apps: as avaliações são lidas no console
// do Firebase (Firestore Database → Dados → coleção feedback).

    match /feedback/{id} {
      allow create: if
        request.resource.data.keys().hasOnly(['esquema', 'app', 'versao', 'nota', 'tipo', 'mensagem', 'contato', 'tela', 'categoria', 'gravidade', 'tecnico', 'enviadoEm'])
        && request.resource.data.keys().hasAll(['esquema', 'app', 'versao', 'nota', 'tipo', 'mensagem', 'enviadoEm'])
        && request.resource.data.esquema == 1
        && request.resource.data.app in ['conta-facil', 'eletrica-facil', 'estudo-facil']
        && request.resource.data.versao is string && request.resource.data.versao.size() <= 20
        && request.resource.data.nota is int && request.resource.data.nota >= 0 && request.resource.data.nota <= 5
        && request.resource.data.tipo in ['avaliacao', 'elogio', 'sugestao', 'critica', 'problema']
        && request.resource.data.mensagem is string && request.resource.data.mensagem.size() <= 2000
        && (request.resource.data.nota > 0 || request.resource.data.mensagem.size() > 0)
        && (!('contato' in request.resource.data) || (request.resource.data.contato is string && request.resource.data.contato.size() <= 120))
        && (!('tela' in request.resource.data) || (request.resource.data.tela is string && request.resource.data.tela.size() <= 60))
        && (!('categoria' in request.resource.data) || request.resource.data.categoria in ['funcionamento', 'erro', 'dados', 'tela', 'outro'])
        && (!('gravidade' in request.resource.data) || request.resource.data.gravidade in ['baixa', 'media', 'alta'])
        && (!('tecnico' in request.resource.data) || (request.resource.data.tecnico is map
              && request.resource.data.tecnico.keys().hasOnly(['plataforma', 'navegador', 'tela', 'janela', 'instalado', 'idioma', 'erros'])))
        && request.resource.data.enviadoEm is timestamp;
      allow read, update, delete: if false;
    }

// Prazo de guarda (política de privacidade, decisões de 29/10/2026): avaliações por 2 anos; comandas ao vivo por 30 dias
// depois de criadas ou encerradas. No plano gratuito (Spark) o Firestore recusa a exclusão automática (TTL, erro 403),
// então a limpeza é MANUAL, uma vez por mês, no console do Firebase → Firestore → Dados:
// 1. coleção `mesas` → Filtrar → campo `expiraEm`, condição "<", valor: a data de hoje → apagar os documentos listados;
// 2. coleção `feedback` → Filtrar → campo `enviadoEm`, condição "<", valor: a data de hoje menos 2 anos → apagar os
//    documentos listados (a primeira vez que algo vence é em outubro de 2028);
// 3. só uma vez: as comandas ao vivo criadas antes do Conta Fácil 1.3.2 não têm `expiraEm`. Apague as que tiverem
//    `createdAt` menor que 1793242800000 (29/10/2026, 0h de Brasília).
// Se um dia o projeto for para o plano Blaze, troque a limpeza manual por políticas de TTL (Google Cloud console →
// Firestore → Time-to-live): `feedback`/`enviadoEm` com adiamento de 730 dias e `mesas`/`expiraEm` sem adiamento.
// A regra de `/mesas` publicada aceita o campo `expiraEm` (o update não restringe campos).
